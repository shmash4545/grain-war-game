# 糧戰：雙城經營戰 V2

繁體中文 React + TypeScript 經營策略遊戲。支援同機輪流及伺服器權威的 2–6 城多人房間；保留 V1 的跨週耕作與四次採買規則。

## 可操作功能

- 首頁、逐步教學、關主自訂 2–6 城、房間碼加入及私人憑證恢復。
- 每城獨立畫面；關主在當週揭曉前只看到加入／連線／提交狀態。已公開歷史可重播。
- 跨週播種、照料、自動收成、正常交付、月結、八週排名及交付趨勢。
- 資料驅動的共同事件、可選取捨、臨時訂單及分帳交付。
- 關主暫停／恢復，或重開所有城市本週操作；已公開週別不能重開。
- 五種城主風格、可解釋證據、主副類型（證據不足時保守顯示）、原創向量城主及 1200×1500 PNG 下載。
- 細化 SVG 村莊：城門、糧倉、市集、橋、農田狀態、糧袋、雨天／晴天／風、旗幟、水流、禾苗與收成提示動畫。無外部圖片、字型或大型圖檔，支援減少動態效果偏好。

## 快速開發

需要 **Node.js 24**（伺服器使用內建 SQLite，不能使用 Node 20）。

```sh
cd /workspace/grain-war-game
npm ci --cache /tmp/grain-npm-cache
npm run server
# 另一個終端
npm run dev -- --port 5173
```

本機瀏覽 `http://localhost:5173/grain-war-game/`。單機不需要啟動 server。多人模式輸入 `http://localhost:3001`，關主建局後，把六位房間碼告訴玩家。正式環境必須使用 HTTPS 的後端網址。

```sh
npm test               # 規則、評分、權限、持久化與 HTTP / SSE 測試
npm run build          # 前後端 TypeScript 檢查 + 前端正式建置
npm run preview -- --port 4173
```

瀏覽器端到端測試（自動啟動獨立測試服務）：

```sh
npx playwright install --with-deps chromium
npm run test:e2e
# 如系統已有 Chromium：
CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:e2e
```

測試資料在 `.data/e2e.sqlite`，與日常房間資料分開。測試每次建立新房間；輸出圖卡、截圖與失敗 trace 在忽略的 `test-results/`。端到端測試會實際操作不同瀏覽器上下文的關主與玩家，涵蓋八週、私密資料隔離、控場、刷新恢復、事件、訂單及 PNG。

## 最容易上線的方式：GitHub Pages + Render 房間服務

**目前程式可本機運行，但後端不會因合併 PR 自動出現在網際網路。沒有替使用者開通帳號或付費服務。**

前端繼續放在 GitHub Pages；多人服務另放在支援 Node.js 24、長連線及持久磁碟的單實例服務。這裡提供 Render Blueprint 作為建議方案。持久磁碟通常需要付費，建立前請在 Render 確認當下方案與價格；未開通時，仍可完整玩單機。

1. 將 V2 PR 合併到 `main`。GitHub Pages 的單機、事件、圖卡與新美術會照既有流程更新。
2. 在 Render 登入並連接 GitHub，僅授權此私有儲存庫。選 **New → Blueprint**，選此儲存庫與 `main`；檢閱 `render.yaml`，確認付費服務及 1GB 持久磁碟後才建立。
3. 部署使用 `Dockerfile`。`ALLOWED_ORIGINS` 預設為 `https://shmash4545.github.io`（只填來源，不含 `/grain-war-game/`）。資料庫路徑 `/var/data/rooms.sqlite` 必須掛在持久磁碟上。
4. 等待 Render 顯示服務正常，取得 HTTPS 網址，例如 `https://你建立的服務.onrender.com`。開啟 `/health` 應看到 `{"ok":true}`。
5. 遊戲內「多人連線」及「加入多人房間」輸入這個相同網址即可，不需要 API 金鑰。
6. 若希望玩家免填網址：GitHub 專案 **Settings → Secrets and variables → Actions → Variables → New repository variable**，新增 **`VITE_API_URL`**，值為上面的 HTTPS 網址；再重跑 `main` 的 Pages 工作流程。此值是公開服務位址，不是 secret。
7. 各城用自己的手機／電腦開啟 Pages，關主先建局並分享房間碼，各城加入不同城市；關主最後開始。正式活動前，先做一次跨裝置測試。

也可用其他容器主機：`docker build -t grain-war-rooms .`，掛載可寫入的持久 volume 到 `/var/data`，設定 `ALLOWED_ORIGINS`，再以 HTTPS 反向代理轉送服務與 SSE 長連線。容器以非 root 的 node 使用者執行；自行掛載主機資料夾時，請確保其對容器內 node 使用者（UID 1000）可寫。不要在未掛持久磁碟的暫存容器裡舉辦正式場次。

### GitHub Pages 設定

**Settings → Pages → Build and deployment → Source → GitHub Actions**。PR 執行測試／建置，只有 `main` push 或手動執行才部署；不提供逐 PR 公開預覽網址。成功後從 **Settings → Pages → Visit site** 進入。

私有儲存庫的 Pages 通常需要 Pro、Team 或 Enterprise 等支援方案；私有來源不代表網站私有。網站存取控制另有企業方案限制，請以 GitHub 帳號方案為準。不會修改儲存庫可見性。

- https://docs.github.com/en/pages/getting-started-with-github-pages/about-github-pages
- https://docs.github.com/en/pages/getting-started-with-github-pages/changing-the-visibility-of-your-github-pages-site

### 環境設定

`.env.example` 是設定名稱說明；Node 服務直接讀取程序環境，沒有自動讀取 `.env`。Vite 的 `VITE_*` 可放在忽略的 `.env.local`，且**會公開進入前端產物**。

| 名稱 | 用途 | 預設 |
|---|---|---|
| `PORT` | 房間服務監聽埠 | `3001` |
| `DATA_FILE` | SQLite 持久資料庫路徑 | `.data/rooms.sqlite` |
| `ALLOWED_ORIGINS` | 允許的前端來源，逗號分隔，包含協定；不含路徑 | localhost / 127.0.0.1 的 5173、4173 |
| `VITE_API_URL` | 可選的公開房間服務位址 | 手動填寫，本機預設 localhost:3001 |
| `BASE_PATH` | 前端網址子路徑 | `/grain-war-game/` |

多人後端必須是**單實例／單程序**：SQLite 與 SSE 廣播都在同一實例。不要水平擴展到多個容器，也不要用多 worker；要擴展需改為共用資料庫與 pub/sub。服務使用程序環境中的持久路徑，不存任何 GitHub 或雲端金鑰。

## 遊戲規則與暫行參數

參數集中在 `src/gameConfig.ts`，未宣稱已平衡。

- 八週、每月四週；每城起始 8 箱、三塊相同農田；通常每週四次行動。
- 播種消耗一次；最早下一週才能照料，照料消耗一次；再下一週週初自動收成 7 箱並回空田。
- 採買消耗一次、通常獲得 2 箱，每週最多四次，與農務共用行動。
- 正常交付不消耗行動，基本每週 6 箱；可超額、不足不淘汰。月目標 32 / 44 箱。第八週照料的田不會產生第九週糧食，但仍計期末產能。
- 事件在週初收成**之後**生效：W3 三次行動；W5 自選 −1 行動換 +3 箱或維持原計畫，必須在農務前選擇；W6 採買每次 3 箱；W7 五次行動。
- W4 臨時訂單 4 箱，履約 +3／失約 −2；W7 訂單 6 箱，履約 +4／失約 −3。均在當週提交時扣庫存，揭曉時結算。正常交付與訂單分帳，訂單不計月目標；拒單不扣分，接單後不能更改。可部分履約但仍視為失約。
- 提交立即預留／扣除正常及訂單交付，不重複結算。全城提交後關主才可公開。
- 暫停只在經營階段使用。重開清除**所有城市當週**操作，還原收成與事件前置選擇完成前的週初快照，保持暫停；恢復後重新決策，不會再重複收成。

### 配分（100 分上限）

- 月目標 35：兩個月各自達成比例封頂 100%，取平均乘 35。
- 超額 25：正常交付超過 48 箱的部分，最多計 24 箱。
- 儲備／產能 25：期末庫存 + 每塊非空田 3 箱等值，最多計 20 箱。
- 韌性／履約 15：15 − 每週缺交合計 + 訂單分數，限制在 0～15。履約正分可抵銷缺交扣分，但不能突破上限。

### 城主風格與證據界線

鑑定描述**本場城市團隊**，不等於個人人格、績效或歷史人物人格。至少六週完整的行為觀察、八次有效行動及兩項相互支持證據才提供主類型；次類型需另有足夠證據，否則明示不足。

- 精算：多週行動利用與基本交付同時達成。
- 開拓：累積農務投入且有超額交付。
- 穩健：多週交付後仍有安全緩衝，同時維持農務投入。
- 應變：多個事件週投入農務並完成交付，且有成功履約紀錄；只是初步行為線索，不宣稱已證明事件造成調整。
- 守成：多次**已完成基本交付**、仍有安全庫存、有期內可收成的成長機會及剩餘行動，卻未繼續投入。拒單或高庫存本身不是證據。

指標為可重現實數：穩定＝完成基本交付週數／8；成長投入＝農務行動數／16（封頂 100%）；有效事件週＝事件週有農務投入且完成交付的週數。規則引擎仍須透過課程實測校準，非科學心理量表。

## 儲存、恢復及權限

- 單機資料放在瀏覽器 localStorage。保留 V1 存檔，缺少播種週次的田視為讀取當週播種；舊週報缺乏行為紀錄，不補造鑑定證據。沒有快照的舊回合不可重開，下一週起可用。
- 多人資料在伺服器 SQLite；前端 localStorage 只保存房間／操作憑證與服務位址。私人憑證不會進入其他玩家的 API 資料或網址。
- 每城只能領取一次；憑證可以恢復同城。每次恢復換發操作 lease，舊頁面即使拿著原憑證，也不能使用舊 lease 操作。可由持有私人憑證者明確取回操作權。
- 不同裝置恢復需房間碼與私人憑證；憑證遺失無法單憑房間碼找回。清除瀏覽器資料前應私下備份。房間碼不是管理密碼。
- 每次操作附 revision 與 idempotency key；SQLite 交易原子保存房間與去重紀錄。過期請求拒絕，相同請求重送不會重扣。重開後舊請求不能影響新決策。
- 網路錯誤時保留未確認的操作，提供使用相同識別碼的安全重試；重連從伺服器取得狀態，不用瀏覽器副本覆蓋伺服器。
- CORS 僅允許設定來源；基本請求頻率及大小限制。公開網路的大型活動仍建議在反向代理加上流量控制及監控。
- SQLite（含 WAL）含私人策略及憑證雜湊，請使用主機的磁碟快照／一致性備份，不要把資料庫提交到 Git，也不要把執行中的主檔單獨拷貝當成完整備份。

## 架構

- `src/gameEngine.ts`：純函式處理經營、交付、事件、訂單、回合及計分。
- `src/assessment.ts`：證據式風格規則。
- `server/store.ts`：SQLite 交易、權限、快照、去重與安全的角色投影。
- `server/app.ts`：原生 HTTP API、授權 SSE、CORS；`server/index.ts` 啟動。
- `src/online.ts`：授權串流、重連、操作權恢復及安全重試。
- `src/GamePanels.tsx` / `OnlineGame.tsx`：共用遊戲與關主／玩家畫面。
- `src/Scene.tsx` / `v2.css`：輕量向量場景與動畫。
- `src/ResultCard.tsx`：原創向量城主、真實數字與 Canvas PNG 匯出；匯出工具延後載入。

## 邊界與後續

沒有上線後端前，多人功能只在本機驗證，Pages 本身不能當伺服器。未實作隨機事件大型卡池、完整 PDF、個人自猜、雲端永久圖卡、帳號管理及跨伺服器擴展。美術為原創向量，不是正式大型角色插畫。配分、訂單獎懲、風格門檻及早期缺交壓力仍需試玩校準。
